# 分辨率术语与自定义推理

U1.5 正式版报告中的“原生 4K”表示训练扩展至 **4096×4096（16.78 MP）**，不是约 4MP，也不表示默认 UHD 输出。原生指直接像素空间生成，而非增加放大阶段。

报告第 2.1 节/图 3 使用 4096² 噪声尺度参考；第 3.2 节/表 2 的初始训练为 256²–1024²，后续高分辨率阶段为 512²–4096²。第 3.2 节 Stage 5 按 {1024², 1536², 2048², 3072², 4096²} 总面积和多种宽高比采样，并对齐到 32。此范围不是统一的最长边上限，也没有列出所有精确训练尺寸。公开 PT 启动脚本仅配置初始 256²–1024² 阶段（序列长度 8192），不是完整高分辨率 recipe。

当前 T2I 推荐表仅为约 **4MP 总面积**：1:1 为 2048×2048，16:9 为 2720×1536，3:1 最长边为 3456。**表中没有标准 UHD 或 4096 级 bucket。** ComfyUI 编辑的 `Auto · 4MP` 同样是 2048² 输出面积策略。

自定义宽、高须为正的 **32 倍数**。3840×2160 的高度不兼容；可尝试 3840×2176，必要时另行裁剪，裁剪不属于原生精确 UHD 输出。4096×4096 明确属于正式版报告的训练分辨率/面积分布；3840×2176 可以被代码接受，但报告未证明这个精确尺寸的训练覆盖。正式版报告不能自动套用到 U1 或 Preview。

[英文说明](resolution.md)提供证据链接和 4096² 完整命令。起始参数沿用 base 默认值：`--batch_size 1 --dtype bfloat16 --cfg_scale 4.0 --cfg_norm none --timestep_shift 3.0 --num_steps 50 --seed 42 --profile`，并非单独验证的 4K 最佳参数；8-step LoRA 应使用对应指南参数。

2048²、3840×2176、4096² 分别对应 4096、8160、16384 个视觉 token，显存与计算开销会显著增加，可能 OOM。本说明未进行 GPU 实测，未给出通用显存要求。量化/offload 降低权重占用，无法消除激活开销；请使用 batch 1 测量，显存不足时降低输出面积或换用更大显存硬件。

模型说明建议统一为：**“原生高分辨率生成，训练覆盖至 4096×4096；参考推理默认使用约 4MP 档位。”** 此仓库修改不会自动同步外部 Hugging Face / ModelScope 模型卡。
