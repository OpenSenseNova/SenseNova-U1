# 新增模型文档

<p align="center"><a href="./model_release.md">English</a> | <strong>简体中文</strong></p>

这份流程用于在本仓库新增可直接运行的官方权重。[模型目录](../models_CN.md)也可收录 SFT 权重和社区转换版本，并链接各自的模型卡；[项目首页](../../README_CN.md#模型指南与案例)只列同时有指南和案例的版本。

## 1. 核对权重和任务

从官方模型卡确认权重仓库、revision、发布阶段，以及基座和适配器的关系。再对照仓库的[推理脚本](../../examples/README_CN.md)，核对文生图、图像编辑、图文交错和视觉问答分别能否运行。不要凭系列名称推断四种任务都支持。

确认模型使用共用的 Python 环境，还是另一套服务框架。实际运行准备公开的命令；如果尚未在当前代码版本验证，就在指南中写明。

## 2. 写模型指南和效果案例

| `docs/` 下的文件 | 写什么 |
| --- | --- |
| `<release>_model_CN.md` | 模型用途、官方权重和适配器、支持的任务、各独立用法所需的简短起步命令、本模型特有参数、少量有出处的选型数据和已知限制。链接到效果案例。 |
| `<release>_showcases_CN.md` | 按实际展示的任务组织案例，写明权重、适配器、输入图、提示词、输出图，以及是否使用提示词增强。链接回模型指南。 |

两页都要有英文版。工作流相同的版本可以共用一对页面，例如 [U1 信息图系列](../u1_infographic_model_CN.md)。LoRA 通常写进基座模型指南；只有工作流和案例都足够独立时，才单独建页。

原版 U1 效果展示沿用已发布的 `docs/showcases.md` 和 `docs/showcases_CN.md` 路径。新增页面仍按上表带版本命名。

## 3. 安放其他资料

- Python 环境链接到[安装指南](../installation_CN.md)，通用参数链接到[任务示例](../../examples/README_CN.md)。模型指南只保留该权重不同用法所需的简短命令。
- 模型卡是权重、版本和许可证的来源；论文与技术报告承载架构、训练和完整实验分析。指南概括读者选型所需的结论并链接原文，不复制整篇报告。
- 发布评测在指南中保留关键结果；较长的逐项对比表可放入 `docs/evaluations/`，如 [Preview 发布评测](../evaluations/u1.5_preview_release_CN.md)和[信息图版本评测](../evaluations/u1_infographic_release_CN.md)。若缺少完整评测配置或权重 revision，应标明它们是发布资料，不能称为当前可复现结果。
- 显存和耗时数据归属所测的模型版本。记录权重与适配器 revision、代码提交、测试日期、GPU 和驱动、主要依赖版本、任务参数、运行次数及指标口径。篇幅较长时单独成页，例如 [U1.5 推理记录](../u1.5_inference_CN.md)。权重或运行代码变更后，复测才能把数值称为当前结果；缺少关键版本信息的数据不要发布为实测结论。
- 提示词增强可选。用法单独写，例如 [U1.5 提示词增强](../u1.5_best_practices_CN.md)；案例要注明是否使用增强。
- 换用其他服务框架时，另写部署说明并注明适用权重。现有 [U1 LightLLM + LightX2V 部署](../deployment_CN.md)和[架构说明](../inference_infra_CN.md)就是一条独立路径。

## 4. 更新入口并检查

1. 在[模型目录](../models_CN.md)加入官方权重与适配器，写清适配器对应的基座；社区权重和工具放在社区分组。
2. 在首页的[模型指南与案例](../../README_CN.md#模型指南与案例)表中同时加入指南和案例。
3. 新版本改变首页主推模型，或有值得公告的发布时，再更新[项目首页](../../README_CN.md)。
4. 检查中英文互跳、图片路径和标题锚点。已在主分支发布的路径尽量保留。
